# تشغيل مجاني ومنع الرصيد المدفوع

أمر المالك: المدفوع للضرورة القصوى فقط، ولا يُصرف شيء افتراضياً. الموافقة على إنجاز المهمة ليست موافقة مالية. الاستثناء يحتاج تكلفة متوقعة وسقفاً وسبباً وبدائل مجانية مستنفدة ثم موافقة صريحة.

- قبل `workflow_dispatch` أو push أو PR أو تعديل `schedule`: افحص محفّزاته ونوع runner وخصوصية المستودع والحصّة. وجود `ubuntu-latest` لا يعني المجانية. لا تعتمد على توقّف GitHub عند الميزانية؛ قد يسمح بمزيد من الصرف.
- عند نفاد الحصّة أو تعذّر إثبات المجانية: أوقف المسارات القابلة للفوترة بشكلٍ قابلٍ للعكس، وسجّل id والحالة السابقة. ألغِ التشغيل المدفوع الجاري أو المنتظر ضمن النطاق. لا تحذف الأدلّة أو الأصول، ولا تغيّر بوّابات الجودة لإظهار نجاحٍ زائف.
- ابدأ ببيئة سحابية متاحة بلا تكلفة إضافية، أو CI مجاني لمشروع عام مع runner قياسي حين يكون نشر مصدره ومخرجاته مأذوناً أصلاً. لا تجعل المستودع الخاص عاماً ولا تسرّب مصدره أو أسراره أو أثره لتفادي الفوترة. ثم استخدم بيئة الجلسة أو التنفيذ المحلي مع الكاش. تحقّق من المجانية الحالية لأي self-hosted، ومن الحوسبة والتخزين والنقل عند المزوّد؛ لا تفترضها.
- لا تعِد البناء أو المحاكي على الرأس نفسه بلا سبب. استعد AAB الموقّعة وتحقّق بالبصمة والتوقيع. اجمع الاختبارات المطلوبة، وامنع ازدواج push/PR، وفعّل إلغاء القديم حيث لا يؤذي النشر.
- التخزين والكاش قد تكون لهما فوترة مستقلّة عن الدقائق؛ تعطيل workflow لا يمحوها. افحص التقرير ولا تحذف أدلّةً ضرورية عمياناً. اقصر الاحتفاظ بالمخرجات المستقبلية على الحاجة الموثّقة.
- لا ترفع حدّ الميزانية ولا تشترِ أرصدة ولا توسّع OAuth للفوترة تلقائياً. غياب وصول الفوترة يُذكر، ولا تُنسب مبالغ دقيقة لجلسةٍ من مدّة تشغيل وحدها.
- أخبر جلسات المشروع، وحدّث دورات متابعتها القائمة ونسخة المهارة السحابية. يستمرّ العمل المجاني، وتبقى بوّابات النشر المطلوبة غير مكتملة إذا لم تُختبر.

مرجع التسعير الرسمي (راجع حالته عند اتخاذ قرار جديد): https://docs.github.com/en/billing/concepts/product-billing/github-actions — المشغّلات القياسية للمستودعات العامة مجانية بحسب الوثائق، والخاصة تستخدم الحصّة المضمَّنة ثم تُحاسَب. لا تعمّم ذلك على المشغّلات الكبيرة أو التخزين.
