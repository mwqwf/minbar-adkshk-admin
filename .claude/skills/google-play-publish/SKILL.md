# نشر Google Play آلياً

الافتراضي في العمل الطويل تنفيذ سحابي مجاني متحقق. يُستخدم GitHub Actions فقط بعد إثبات أن التشغيل لن يستهلك الرصيد المدفوع، مع حساب الخدمة المحفوظ للمشروع. إذن النشر والمسار يؤخذان من الطلب وقواعد المشروع؛ لا تفترض الإنتاج أو تستعير بيانات مشروع آخر. لا تطلب تكرار إذن واضح.

## عند عائق إقرار أمان البيانات

لا تعتبر غياب جلسة Play Console عائقاً قبل تجربة واجهة Google الرسمية:

`POST https://androidpublisher.googleapis.com/androidpublisher/v3/applications/{packageName}/dataSafety`

الطلب JSON: `{"safetyLabels": "<نص CSV كاملاً>"}`. نطاق OAuth هو `https://www.googleapis.com/auth/androidpublisher`؛ الاستجابة الناجحة HTTP 200 أو 204 وجسم فارغ (204 متحقق فعلياً). المرجع الرسمي: [applications.dataSafety](https://developers.google.com/android-publisher/api-ref/rest/v3/applications/dataSafety).

1. راجع سلوك النسخة الفعلي وتدفقات البيانات وسياسات الخصوصية والحذف. ولّد CSV من قالب Google الحالي باستخدام إجابات المشروع المقيسة؛ لا تنقل إجابات مشروع آخر. لا تعتبر تشخيصات تلقائية اختيارية ولا تدّع حذفاً غير منفذ.
2. تحقق من الصفحات المنشورة نفسها وقارنها بالمصدر الموافق للإصدار. احتفظ بالقالب الأصلي ولا تكتب فوقه.
3. استخدم حساب خدمة Play المصرح للمشروع داخل CI. لا تُظهر الأسرار ولا تنسخها للمحادثة أو artifact، ولا تنشئ صلاحيات جديدة لمجرد تعذر الواجهة.
4. أرسل الإقرار. احتفظ بإيصال يحتوي الحزمة وHTTP الفعلي ووقت UTC وبصمة CSV وبصمات تدفق البيانات والخصوصية ورقم الإصدار ورابط تشغيل CI. لا تجعل الموافقة true قبل نجاح الإرسال، ولا تنشئ رابط Console وهمياً. إذا اشترط حارس قديم Console حصراً، أضف قبول إيصال API الصحيح باختبارات رفض للفشل والبصمات القديمة والحزمة الخاطئة، بدلاً من تعطيل الحارس.
5. صنّف الرفض من نص Google: 400 يعني غالباً نموذجاً غير صالح، 401 اعتماداً، 403 صلاحية. أصلح السبب ضمن النطاق. لا تكرر عميانياً ولا تتجاوز رفض المنصة. عند نتيجة شبكة ملتبسة لا تدّع النجاح؛ يجوز إعادة الإقرار نفسه مرة محدودة ثم توثيق النتيجة.

## بناء الإصدار والتحقق

بعد نجاح الإقرار والاختبارات المطلوبة: اختر versionCode غير مستخدم، وحدّث الملاحظات، وابنِ ووقّع في CI، وارفع فقط إلى المسار المأذون. أعد ربط دليل الإقرار بالنسخة النهائية بعد تغيير كود الإصدار.

اقرأ `edits.tracks.get` في edit جديد بعد commit النشر، وتحقق من versionCode وحالة الإصدار في المسار المقصود. احذف edit التحقق غير الملتزم فقط. نجاح HTTP للإقرار لا يثبت انتهاء مراجعة المتجر؛ ونجاح بناء AAB لا يثبت النشر. ميّز بين رفع الحزمة، إرسالها للمراجعة، وإتاحتها للمختبرين.

لا تعدّل حواجز الجودة أو تزوّر دليلاً لتسريع النشر. لا ترفع نسخة ثانية لمجرد إعادة المحاولة إذا كانت الأولى موجودة؛ اقرأ المسار أولاً. وثّق النتيجة ورابط CI والعمل المتبقي سحابياً.

عند حفظ اعتماد JSON بـgh: تحقق من بنيته دون طباعته، ثم مرّر البايتات عبر stdin إلى gh secret set NAME --repo OWNER/REPO دون --body؛ تمرير --body بقيمة شرطة يحفظ الشرطة نفسها ولا يقرأ stdin. لا تدوّر المفتاح لمجرد فساد صيغة السر المحفوظ.

## إذا ظهر رفض Foreground Service عند commit

نجاح DataSafety لا يغطي إقرارات الخدمات الأمامية. صنّف رسالة Google بدقة. راجع واجهة API الرسمية الحالية؛ حتى revision20260917 لا توجد طريقة FGS عامة لتطبيقات Play ، وواجهات appstoreappsreview تخص المتاجر الخارجية. أكمل نموذج App content عبر جلسة Console المخولة، وجهّز وصف كل خدمة وأثر تأخيرها/انقطاعها وفيديو فعلي لبدئها وإيقافها من التطبيق. لا تختلق فيديو أو رابطاً، ولا تحذف صلاحيات لازمة أو تخفض targetSdk للتحايل.

إذا فشل commit بعد رفع AAB ، احتفظ بالأثر الموقّع ورابط التشغيل ورقم الإصدار، وافحص tracks/bundles قبل إعادة المحاولة. استعد نفس AAB سحابياً عند صلاحيتها بدلاً من بناء نسخة جديدة أو زيادة الرقم. ميّز عائق اتصال الإضافة أو تسجيل الدخول عن غياب إذن المالك؛ لا تطلب إذن نشر مُنح بالفعل. وثّق المتبقي وأكمل الأعمال المستقلة عنه.

## حد الإنفاق في GitHub Actions — أمر المالك 2026-09-18

يحظر استهلاك الرصيد المدفوع افتراضياً، ولو كان البناء أو النشر مأذوناً. المدفوع للضرورة القصوى فقط وبعد موافقة مالية صريحة على السبب والتكلفة والسقف؛ توافر ميزانية لا يساوي الإذن. افحص تكلفة runner والحصة ومحفزات push/PR/schedule قبل التشغيل والدفع. إذا تعذر إثبات المجانية فلا تطلق التشغيل. ابحث أولاً عن تنفيذ سحابي مجاني متحقق، ثم بيئة الجلسة المتاحة، ثم الجهاز بكاش وأقل استهلاك. لا تجعل المستودع الخاص عاماً ولا تنقل أسراره أو كوده إلى أثر عام لتوفير المال. لا تكرر الاختبارات والبناء على الرأس نفسه، واستعد الحزمة المتحققة. لا تعِد تفعيل مسارات أوقفت بسبب التكلفة قبل تأمين بديل مجاني أو إذن مالي محدد. التفاصيل في مهارة github-actions-cost-control.
